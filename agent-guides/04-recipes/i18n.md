# Labels in several languages

Catalogs are flat JSON files under `custom/i18n/`, one per locale, registered once in
`custom/index.ts`:

```ts
import en from './i18n/en.json';
import fr from './i18n/fr.json';

provideWebUiMessages('acme.labels', { 'en-US': en, fr });
```

Lookup order: the explicit locale, then its base language, then `en-US`, then the literal
fallback. Keep every key in `en-US`. Keys are yours; prefix them with the owner prefix, except
the Nuxeo Studio keys below, which keep the Web UI's names.

Where a key is used:

- `labelKey` next to `label` on document views, paired views, drawer items (`inputs.labelKey`),
  themes, layout fields and sections. `label` stays as the fallback.
- `{{ 'acme.contract.approve' | webuiMessage: 'Approve' }}` in a template (`imports:
[WebUiMessagePipe]`). The pipe follows locale changes and interpolates `{0}`, `{1}` as text;
  it never renders HTML.
- `context.reportMessage?.('acme.contract.approved', 'Contract approved')`: the host formats and
  reformats the message when the locale changes.

The application's own catalogs (`POLYMER_MESSAGES`, `app.*` keys) are core; add your keys, do not
edit theirs. Romanian stock labels fall back to English; a `custom/i18n/` catalog can supply them.

## Nuxeo Studio translations

The UI reads no catalog from the server. The stock Web UI fetches `ui/i18n/messages*.json` from
Nuxeo at runtime, and a Nuxeo Studio project adds its labels to that file: document types, schema
fields, vocabulary entries and the keys the project wrote. This UI ships its catalog in the build,
so those labels move into `custom/i18n/`, once per Studio project and again whenever its
translations change:

1. Take the project's translation files, one per language: `messages.json` (English),
   `messages-fr.json`, and so on. Studio Designer edits them under Translations; a Nuxeo server
   with the Studio package installed serves the merged result at `/nuxeo/ui/i18n/` (sign in
   first).
2. Keep the project's own labels and drop the unchanged stock ones. This UI already has the stock
   labels in every supported language, and a copied stock key would override that wording
   (`custom/` catalogs sit above core). With the stock `i18n/messages.json` of the matching
   `nuxeo-web-ui` release at hand, per language:

   ```sh
   node -e '
   const studio = require("./messages.json"), stock = require("./stock/messages.json");
   const own = Object.fromEntries(Object.entries(studio).filter(([k, v]) => stock[k] !== v));
   require("fs").writeFileSync("custom/i18n/en.json", JSON.stringify(own, null, 2) + "\n");'
   ```

   The result keeps the project's additions and its deliberate overrides of stock labels.

3. Register the files once in `custom/index.ts`, as above:
   `provideWebUiMessages('acme.studio', { 'en-US': en, fr })`. The keys keep their Studio names
   (`label.document.type.<type>`, `label.schema.<schema>.<field>`,
   `label.directories.<vocabulary>.<entry>`, the project's own keys): the UI looks type, field
   and vocabulary labels up under them. Do not add the owner prefix to them.
4. `npm run verify`.

Example: [en.json](../../examples/acme/custom/i18n/en.json), [fr.json](../../examples/acme/custom/i18n/fr.json),
the registration and `labelKey`s in [index.ts](../../examples/acme/custom/index.ts).

Then `npm run verify`. Reference: [Icons, labels and theme source catalogs](../../app/extensions/README.md#icons-labels-and-theme-source-catalogs).

# WebUI internationalization checks

The production languages are `en-US`, `es`, `fr`, `ar`, `ro`, `pt-PT` and `it`. The application and SDK share `WebUiLocale`; `WebUiMessages` formats complete ICU messages. The legacy Angular translation bridge consumes the same resolved catalogs. `custom/` overrides remain the final message layer.

Translate app-owned instructions, labels, errors and accessible names through explicit keys. Keep repository titles, bodies, filenames, comments, users, custom directory labels, identifiers and supplied literal labels unchanged. `labelKey` or `messageKey` explicitly opts a custom label into localization. Never infer ownership from English spelling or a dotted string. Named message parameters are values, not message keys.

## Commands

- `npm run i18n:inventory` records template, TypeScript and JSON candidates in `dist/verification/i18n/source-inventory.json` and `.md`.
- `npm run verify:i18n` checks all seven resolved catalogs, ICU contracts and exact source reviews. A missing translation, blank value, incompatible argument/select contract, required plural category, unreviewed source candidate or stale review exits nonzero.
- `npm run verify:i18n-guards` proves positive and negative behavior of the catalog/source/migration/pseudo checks. Tests exercise the actual CLI, not only helper functions.
- `npm run i18n:pseudo` generates `dist/verification/i18n/pseudo.json` from parsed English ICU. It accents and expands literal nodes while preserving message syntax, arguments and selectors. This is a development artifact, not a production locale.
- `npm run test:i18n` starts the isolated local Angular fixture on port 4311, runs the Playwright matrix and validates its exact surface manifest. Use `CHROME_BIN` for a preinstalled Chrome binary. It does not contact an installed Nuxeo server.

`complete-catalogs.mjs` merges reviewed English drafts and authored supplements; it may reuse a translation only for an unambiguous matching English message with a compatible ICU contract. It never fills a missing translation with English. Its report explicitly lists remaining gaps. `write-catalogue-provenance.mjs` records the source of retained/generated entries. Locale review notes document intentional shared spellings, brands and technical tokens; equal text alone is neither proof of failure nor proof of translation quality.

## Source review

The inventory is a conservative static candidate collector, not a proof of every runtime state. Review dynamic values at their producing component. Exact review records contain a SHA-derived identity, file, kind, text, ownership, reason and maximum occurrence count. `source-exceptions-*.json` filenames constrain their permitted path scopes; declarations may narrow those scopes but cannot widen them. Duplicate identities across files, stale records, changed strings and increased counts fail. Review files are deliberately explicit and must not be regenerated by automatically accepting every finding.

An English fallback beside a confirmed message key is different from untranslated UI. A parser diagnostic may retain a stable English programmatic contract only when its actual display path has a reviewed localized adapter. Canonical catalog metadata that is not displayed also differs from its localized runtime presentation. Record those boundaries precisely.

`source-references.mjs` separately checks statically explicit pipe keys, supported message calls/descriptors, keyed metadata/input defaults and the known configuration definition table against the combined English SDK/application catalog. SDK references must also exist in the SDK's own catalog layer, whose seven locales are checked independently. This catches keys missing from every locale and prevents application assets from concealing an incomplete standalone SDK. Computed keys and indirect command maps still require source-origin review; arbitrary runtime values and fields merely named `key` are not inferred as translation requests.

The bounded migration helper defaults to preview:

```sh
node scripts/i18n/migrate-static.mjs app/components --draft /tmp/reviewed-en.json --namespace app.components
```

Add `--write` only after inspecting the report and ownership. It handles static text, human-facing attributes, display branches and literal right-hand `||`/`??` fallbacks. It does not change conditions, property lookups, saved values, `ng-select`'s `bindLabel`, or compound sentences requiring a complete ICU rewrite. It refuses unsafe edits and maintains standalone imports for every consumer of a shared template. Generated keys and English drafts still need semantic review and translations.

## Browser coverage

`e2e/i18n/main.ts` imports real AppComponent, shell/sidebar, user menu, QuickSearch, confirmation dialog and signed-out Unauthorized components with explicit fixture authentication/repository data. It loads production catalogs; Arabic text is not substituted by a fake test catalog. The exact matrix is seven production locales × default/dark themes, plus two pseudo-locale cases: 16 tests and 80 settled surface records.

The five surfaces are shell, user menu, quick search, confirmation and signed-out UI. Assertions verify the selected locale/direction, rendered content, known pseudo activation and preserved unsaved form text. The pseudo audit checks each visible text fragment and accessible attribute; a marker in one fragment cannot hide plain text beside it. `custom/` and autonym exemptions are exact and bounded. The summarizer rejects wrong routes, missing states, skips/retries and failing records.

This matrix does not cover every editor/error/loading/permission state, a Nuxeo-owned login form, native browser/OS dialogs, PDF document content, manual assistive technology or installed/hosted acceptance. The W5 axe/IBM suite is a separate accessibility check with its own documented limitations. Both suites are useful evidence; neither substitutes for fluent-language review or installed acceptance.

Shipped packages keep production catalogs, message/locale runtime and widget dependencies. They exclude the fixture, pseudo artifacts, audit scripts and `i18n` build/serve configuration. The API archive test checks that boundary against the actual shipped archive.

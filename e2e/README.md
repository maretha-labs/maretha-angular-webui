# Accessibility and local Nuxeo checks

Run `npm run test:e2e:compiled-search` to verify the [test-only compiled search](compiled-search/searches.ts). Its [separate entry](compiled-search/main.ts) combines the production router and default UI provider set with an additional search contribution. Playwright uses a synthetic signed-in reader and synthetic Nuxeo page-provider responses intercepted at the HTTP boundary. The tests cover drawer submit, cold deep links, list/table switching, search-specific preferences, and sorting without submitting a drawer draft. This does not verify live Nuxeo authentication or query execution. Set `CHROME_BIN` to a Chromium executable if needed.

CI runs these browser tests in the independent `compiled-search` job. Production provider registration is covered by the application unit suite. `npm run verify:compiled-search-production` builds optimized AOT production output and checks every JavaScript file and JavaScript source map for the fixture ID, message key, and source directory, including lazy chunks. The command uses a temporary 17 kB component stylesheet ceiling because three existing stylesheets on `main` exceed the standard 8 kB ceiling; it leaves the production configuration unchanged. The result is written to `dist/verification/compiled-search/production-exclusion.json`. `node --test scripts/verify-compiled-search-production.test.mjs` verifies the guard rejects deliberate script/source-map leaks and missing output.

`npm run test:a11y` builds and serves a deterministic Angular fixture on `127.0.0.1:4310` and runs headless Playwright. It imports the production `AppComponent`, `SidebarComponent`, shell actions, Quick Search, default user-menu/theme contributions, `ConfirmationDialogComponent`, `UnauthorizedComponent`, SDK actions menu/tooltip, `StandardContentEditorComponent`, `FileUploadComponent` with its default file-action contributions, document tabs, SDK/runtime document trees, and `BaseEditorComponent`. Save/upload outcomes use locally controlled Subjects in `save-fixture.ts`; the production editor renders its own statuses and errors. Authentication, document/task/collection/history data, creation permissions, and search responses are fixture providers. Routed document content and upload callback output are clearly labelled fixtures. Context-level request routing is installed before pages are created, including popup initial requests. Service workers are blocked and WebSockets are closed. HTTP(S) is restricted to loopback addresses. Redirects are rejected before following them, including redirects to another loopback URL; use final URLs with no redirects. This is component integration evidence, not an installed-package or hosted-to-local acceptance run.

Use Node 24.18.0 and `npm ci`. The runner uses `CHROME_BIN` when supplied, otherwise the normal macOS Chrome executable when available, otherwise Playwright's installed Chromium. On a fresh machine install the browser explicitly with `npx playwright install chromium`. There is no implicit browser download in the tests.

The expected matrix declares 64 browser tests and 84 paired scan states (168 engine scans); these are required identities, not a claim that a particular run passed. Read the fresh runner summary for its result. Axe checks WCAG 2/2.1/2.2 A/AA and best practices. IBM Equal Access uses `IBM_Accessibility`. Both engines are loaded from pinned local npm packages, with no runtime rule-service/CDN fetch. Reports record engine, Playwright and browser versions plus observed language and effective theme. Invalid or empty engine reports fail rather than silently counting as a pass: every IBM finding must have rule/reason/path identity and a recognized two-part status tuple. IBM reason IDs permit segmented values such as `Pass_1.2`; this does not broaden the exact reviewed sentinel exception. Dialog scans wait for full opacity, the end of the transform transition, and font loading. Localized headings have explicit text/bounds checks and a separate rendered-color contrast check (at least 4.5:1), since automated engines do not consistently evaluate Arabic text contrast.

`node e2e/a11y/summarize.mjs` validates the independent `expected-matrix.mjs` contract. A matching total alone cannot pass: each test, language/theme, surface and paired attachment must appear exactly where expected. Missing/duplicate/unexpected states, provenance mismatches, malformed reports, skipped/flaky/retried tests and report-level errors fail. A failed summarisation replaces an older passing summary. No fixture test submits repository writes or uploads bytes to Nuxeo. Subject-backed service outcomes cover the editor's UI lifecycle and cancellation/late-result behavior in combination with focused unit tests. The file chooser's OS interface and actual network upload/save lifecycle remain outside this matrix.

Use `npm run test:a11y` for the complete run result. Its runner removes the previous browser report and writes a failing pending summary before starting Playwright, always runs the summariser, and preserves browser-process failures even if a complete report was written. The final summary records both child exit codes. The standalone summariser validates report contents only. CI uses the runner and retains its artifacts even when the run fails.

The gate fails every axe violation and every unreviewed IBM violation. Incomplete axe results and IBM potential/manual/recommendation results remain in evidence for human review; a passing automated gate is not a claim of full WCAG conformance or screen-reader usability. No screen-reader or inclusive-user assessment is performed by this suite.

Manual acceptance still requires screen-reader reading/navigation and error/status speech, visible/unobscured focus beyond the declared states, target size/spacing, actual 200% browser/text zoom and 400% reflow, text spacing across complete workflows, color-only meaning and native Windows high-contrast modes. The current preference tests use a 320 CSS-pixel viewport, 200% root-font enlargement, injected text-spacing overrides and browser forced-colors emulation; they do not perform actual browser zoom or an operating-system high-contrast session. Record platform/browser/assistive-technology versions, exact surface/state, expected and observed behavior, and the reviewer when performing those checks. Headless keyboard tests and forced-colors emulation do not substitute for that record.

## Reviewed third-party finding

The only reviewed exception is IBM `aria_hidden_nontabbable` / reason `Fail_1` for the two ngx-bootstrap 21.2.0 focus-trap sentinels surrounding the **confirmation-dialog** surface. Each must be an empty `div`, a direct child of `modal-container` containing one real `nx-confirmation-dialog`, with exactly the classes `cdk-visually-hidden cdk-focus-trap-anchor`, `tabindex="0"`, and `aria-hidden="true"`. The gate checks actual DOM nodes reached by the reported XPath and fails if more than two match. Other surfaces, elements, attributes, classes, rules, and unexpected counts remain failures. Raw engine violations and separately applied full finding identities (rule ID, reason ID, XPath) are both retained. Matching a reviewed XPath alone never exempts another rule or reason at that node. Scan and summary gates share this exact identity matcher.

This is an explicitly reviewed third-party finding, not a universal claim that the rule is wrong. The installed source `node_modules/ngx-bootstrap/focus-trap/fesm2022/ngx-bootstrap-focus-trap.mjs:420-421` defines immediate first/last-control redirection, `:460-464` attaches the focus listeners, and `:630-631` creates the class and hidden attribute. Browser tests verify both directions reach real buttons, the sentinel never remains active, and Escape restores the initiating control. Review this narrow exception when upgrading ngx-bootstrap or IBM's engine. No axe rule is disabled and no application subtree is excluded.

## Configured local Nuxeo suite

`npm run test:e2e:nuxeo` requires these explicitly supplied settings:

- `NUXEO_E2E_BASE_URL`: installed WebUI root, e.g. `http://127.0.0.1:8080/nuxeo/ng`.
- `NUXEO_E2E_API_URL`: Nuxeo context root, e.g. `http://127.0.0.1:8080/nuxeo`.
- `NUXEO_E2E_STORAGE_STATE`: path to a user-prepared authenticated Playwright storage-state file. Keep it outside the repository and CI artifacts. The suite does not discover or submit credentials.
- `NUXEO_E2E_SESSION_STATE`: optional companion state for the runtime's scoped OAuth `sessionStorage`. Ordinary Playwright storage state omits `sessionStorage`; use the manual capture helper below for the standard Maretha OAuth runtime. The companion is checked for exact application/API scope and a current token, then restored only on that application's path and origin. Keep it outside the checkout and artifacts too.
- `NUXEO_E2E_DOCUMENT_ID`: existing readable, indexed test document ID.
- `NUXEO_E2E_SEARCH_TERM`: optional search text known to return that document; defaults to its ID.

Only final loopback HTTP(S) URLs with no redirects are accepted. Any redirect produces an explicit unsupported-redirect prerequisite failure before it is followed. This restriction includes local redirects and external SSO; supporting such an installation needs an explicit redirect adapter. The anonymous scan opens `/login.jsp` directly and does not exercise a complete login/authentication redirect flow. URL credentials/query/fragment are rejected. No automatic server startup, deployment, remote demo fallback, data creation or deletion occurs. The suite checks the real anonymous Nuxeo login form with both engines, then uses the supplied session for shell/search/document navigation/menu dismissal and opening/cancelling the creation destination. Two separate candidate accessibility checks scan the authenticated dashboard and UI configuration editor with both engines. They require the actual User menu; dashboard loading and error states must settle, and the editor must show the exact application/API/configuration-document identity, saved version and WriteProperties access before scanning. The checks never edit or save configuration. The editor identity guard reports booleans rather than native identity text. A customized or external SSO login needs an explicit adapter and currently fails its precondition. These read-only paths do not cover create/save/upload/delete, media, download completion, permissions permutations, or all document/layout types. Candidate accessibility results remain separate from the vendor login result; a failing vendor login is still a failure of the full suite.

Installed candidates use Angular path routing. Dashboard and UI Configuration entries require an exact origin/application/path match without a query or fragment. Document entry can start at `/browse/documents/<configured-id>`, but the loaded document is canonicalized to its native repository path. For both Quick Search navigation and the creation precondition, the harness reads only the configured document through the supplied browser context's cookie-backed request at the configured loopback Nuxeo API, with redirects disabled. Metadata must return the exact UID, `default` repository and a valid non-version native path. After document views become visible, the final URL must match that exact encoded path beneath the configured application root, either without a query or with only the literal `?view=view`. A transient UID URL, another document/path/repository/application/origin, extra or duplicate queries and any fragment fail. The suite neither discovers nor submits credentials and does not report metadata bodies. Run `node --test e2e/nuxeo/native-route.test.mjs` for canonical identity, metadata transport and wrong-route/query regression guards.

### Prepare the standard OAuth session manually

Start the local Nuxeo server and install the selected local candidate first. Use one hostname consistently; the generated application's Nuxeo URL, OAuth redirect, browser URL and test URL must agree. For an isolated package with artifact ID `maretha-authoring-local` and route `authoring-local`, register an enabled public OAuth client `maretha-authoring-local` with redirect `http://localhost:8080/nuxeo/authoring-local/#`. The test helper does not register a client, deploy packages or change incumbent `/nuxeo/ng` files.

Create one synthetic File with a unique title such as `Maretha native QA fixture` in a dedicated QA workspace through the stock Nuxeo Web UI. Give the selected test identity Read access to that document and only the ordinary creation permission needed to open/cancel the destination dialog; the suite does not persist a new document. Wait until Quick Search returns this exact document and record its ID. Do not use production documents. Permissions/concurrency mutation tests remain a separate authoring campaign with dedicated administrator/editor/reader identities and application configuration.

With Node 24 and existing dependencies/browser, run from the runtime checkout:

```bash
mkdir -m 700 /private/tmp/maretha-nuxeo-qa
export NUXEO_E2E_BASE_URL='http://localhost:8080/nuxeo/authoring-local'
export NUXEO_E2E_API_URL='http://localhost:8080/nuxeo'
export NUXEO_E2E_STORAGE_STATE='/private/tmp/maretha-nuxeo-qa/storage.json'
export NUXEO_E2E_SESSION_STATE='/private/tmp/maretha-nuxeo-qa/session.json'
npm run prepare:e2e:nuxeo
```

The helper opens a fresh visible browser. The human enters the local QA account's credentials and completes sign-in; the helper never reads credentials from files or fills a login form. It allows manual loopback OAuth redirects, blocks remote requests/service workers/WebSockets, waits up to ten minutes for the authenticated User menu, and writes both files with owner-only permissions. Existing output files are rejected: use a new directory for recapture. No token values or DOM are printed. The automated suite retains its stricter no-redirect boundary.

Then set `NUXEO_E2E_DOCUMENT_ID` to the synthetic document's ID and `NUXEO_E2E_SEARCH_TERM` to its unique title, and run `npm run test:e2e:nuxeo` before the token expires. The suite restores only the captured scoped token/validity/refresh entries, not arbitrary session storage. `npm run verify:nuxeo-state` checks expiry, wrong-app/API rejection and origin/path isolation without a Nuxeo server. Authentication files must never enter Git, reports, uploaded artifacts or terminal output. Revoke the QA session and remove only that run's state files and synthetic data during operator cleanup.

Missing configuration, unavailable local server, missing storage state, or failed authentication produces **PRECONDITION NOT MET** and a nonzero exit. It is not skipped or counted as success. The anonymous application reachability probe uses its final trailing-slash URL and accepts 2xx or 401, since an installed application may require sign-in. Only that application probe accepts 401: Nuxeo `/runningstatus` must return 2xx. Both probes reject every redirect before following it. Reachability alone does not establish authentication: the suite still requires the actual authenticated shell. Quick Search matches the configured exact document ID in a native result's metadata, allowing its translated type label, and then requires navigation to that exact document route. Labels or similar IDs cannot substitute. Hosted-to-local package acceptance remains separate. Run `node --test e2e/nuxeo/reachability.test.mjs e2e/nuxeo/quick-search-identity.test.mjs e2e/nuxeo/candidate-identity.test.mjs` for the positive/negative harness guards.

Reports live under `dist/verification/a11y/` and `dist/verification/nuxeo/`. Fixture failures retain local Playwright traces and raw scan reports containing only fixture data. Nuxeo traces, screenshots and video are disabled; all native scan attachments retain rule IDs/counts instead of raw DOM snippets, screenshots or native metadata. Candidate surfaces receive no reviewed fixture exceptions. Do not upload storage state, credentials, browser profiles or HAR files.

Harness guard self-tests: `npm run verify:a11y-guards`. They prove exact matrix integrity, exception identity isolation, malformed-report rejection, stale-summary replacement, sanitized live assertion data, redirect blocking, and exact document route matching.

Run `npm run verify:test-apps` before submitting changes to shared components. It discovers the accessibility/parity, internationalization, compiled-search and preview application entries in `angular.json`, requires `strictTemplates`, and compiles each with Angular's `ngc --noEmit`. Ordinary TypeScript checks do not catch removed or missing Angular template inputs. CI runs this check before the translation gate. For a full accessibility-fixture bundle build, run `npx ng build --configuration a11y --aot --progress=false`.

Standalone browser-test TypeScript check: `npx tsc --noEmit -p e2e/tsconfig.json`. Tests are named `*.e2e.ts` so Karma does not discover them.

Engine integration follows [Playwright's accessibility guidance](https://playwright.dev/docs/accessibility-testing) and the [IBM engine API](https://github.com/IBMa/equal-access/blob/main-4.x/accessibility-checker-engine/README-NPM.md).
